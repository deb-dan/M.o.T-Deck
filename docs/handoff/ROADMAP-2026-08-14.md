## 1c. NEW — the contract gate must be RUNNABLE on Debi's Mac (2026-08-15)
**STATUS: NOTED FOR FABLE, NOT IMPLEMENTED (Debi's instruction 2026-08-15).** No code
was changed; `bridge/requirements.txt` is untouched.

- **The problem:** the pin-bump gate `python -m pytest bridge/contract_tests/` silently
  reported "No module named pytest" during the Hermes v2026.8.13 bump, so **a vendored
  bump shipped with its safety gate skipped**. (Run in the sandbox afterwards it caught
  3 real failures, one behavioural.) Neither the system python nor `data/bridge-venv`
  has pytest, and `data/bridge-venv` has **no pip module either** — `bootstrap.sh:87`
  creates it with `uv venv` (no `--seed`) and installs via `uv pip install`, so the
  obvious `python -m pip install pytest` also fails.
- **Option A (one line):** add `pytest>=8.0` to `bridge/requirements.txt`. Bootstrap
  then installs it everywhere, and it rides into the fat wheelhouse for free because
  `build_app.sh` 4b does `pip download -r bridge/requirements.txt`. Cost: a test
  dependency lives in the runtime requirements file.
- **Option B:** a separate `bridge/dev-requirements.txt`. Cleaner separation; costs a
  second install path that BOTH bootstrap and the fat installer must learn.
- **Option C (orthogonal, arguably the real fix):** make `scripts/ship.sh` — or a new
  `scripts/verify.sh` — RUN the contract suite and **refuse loudly when it cannot**, so
  the gate cannot be silently skipped again regardless of where pytest lives.
- Interim, for an existing install (mirrors bootstrap; `python -m pip` cannot work):
  `source data/bridge-venv/bin/activate && uv pip install pytest && deactivate`

## 2. Fable QA / design gates (mine, next session)
- 🧠 **Debi explicitly asked Fable to review the Hermes auto-reload mechanism
  (2026-08-15, working and verified, but she wants a second opinion on the design):**
  instead of only checking when you switch to the Hermes tab, the shell now polls
  **every 4 seconds while a Hermes pane is actually on screen** and stops the moment
  it isn't (no polling when Hermes is not visible). It reuses the existing generation
  check rather than duplicating logic, and the safety properties hold — bridge
  unreachable → nothing happens, cannot loop, a bridge restart does not trigger a
  spurious reload. Two consequences she wants looked at: (a) with Hermes in **both**

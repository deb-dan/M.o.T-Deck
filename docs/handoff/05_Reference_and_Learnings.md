## ⟳ STATE UPDATE — 2026-08-07 (supersedes sections below where they conflict)

Still a useful fact-file for the upstream projects, but the operational learnings have moved.
Canonical ops reference: `docs/MOT-DECK-INTERNALS.md` §12 (gotchas) and §13 (install footprint);
dated history in `CLAUDE.md`.

Facts that changed:
- **Jan is gone** (July 2026) — every Jan CLI/endpoint learning below is historical. LM Studio is
  now only a **read-only model-import source** (`~/.lmstudio/models` scanned into our registry).
- **Our runner:** `llama-server` (llama.cpp pin `b10295`, always launched with
  `--alias <registry id>`) or `mlx_lm.server`/`mlx_vlm.server`, on :6767.

Ops gotchas learned the hard way since (the expensive ones):
1. **The fat app serves a provisioned snapshot**, not the repo — a `--fat` rebuild never refreshes
   an existing snapshot. Ship only via `./scripts/ship.sh`.
2. **The bridge outlives the app.** Quitting the app does not restart the bridge; use
   `./scripts/ship.sh` when code changed so its pidfile/path ownership checks restart the right bridge.
3. **Every `lsof -ti tcp:` kill MUST carry `-sTCP:LISTEN`** — without it the pattern matches client
   sockets and once SIGTERMed the bridge itself.
4. **WKWebView never delivers DOM drag events** — file drag-and-drop needs a native `DropOverlay`
   forwarding into the page; and without a `runOpenPanelWith` WKUIDelegate method a file `<input>`
   silently no-ops.
5. **Hermes's default `approvals.mode` is `smart`, not manual** — a guardian LLM can auto-approve
   before the approval card path. Set `manual` in Hermes Config → Security.
6. Never kill the bridge or app by name or by a bare port match. For an app-only cycle use
   `osascript -e 'tell application id "local.motdeck.app" to quit'` and then
   `open -b local.motdeck.app`; the installed filename may be `MOT Deck.app` or `M.O.T.app`.

## 1. Tool landscape (the four upstream projects)

### LM Studio
- Closed-source local model runner + chat UI + OpenAI-compatible server (:1234) + MCP host. Free for personal use.
- Strengths: polished UX, excellent HF model browser, MLX backend (fast on Apple Silicon), mature MCP support, `lms` CLI (headless load/serve, `lms get` downloads).
- Weaknesses: proprietary, telemetry on by default, Electron-heavy, Linux beta.
- MOT Deck role: **fallback runner** behind the runner-slot adapter.

### Jan AI
- Open source: **Apache-2.0** (corrected 2026-07-20 — verified root LICENSE + README; the earlier "AGPL app / MIT SDK" split is retired). Tauri/Rust (NOT Electron).
- Already has (the gaps you once thought needed a fork): built-in HF Hub model browser with hardware-fit pills + one-click GGUF download; **native MLX backend since v0.7.7** (Feb 2026 — young; early regressions e.g. issue #7804); **MCP since v0.7.3** (arbitrary servers; per-tool permission gating as of v0.7.9).
- Server modes (verified 2026):
  - Desktop API server: Settings → Local API Server → Start Server; default `127.0.0.1:1337/v1`; OpenAI-compatible (`/v1/models`, `/v1/chat/completions` with streaming + tool calling) plus Anthropic-compatible `/v1/messages`; `/v1/responses` "coming soon". Optional API key, host/port/CORS configurable.
  - **CLI since v0.7.8** (auto-installed to `/usr/local/bin/jan` or `~/.local/bin/jan`): `jan serve [MODEL_ID]` → `localhost:6767/v1`, flags `--port`, `--api-key`, `--detach`; also `jan launch`, `jan models`, `jan threads`. **`jan serve <hf-repo-id>` auto-downloads the model** — this is the Bridge's download mechanism, because:
  - **No HTTP download endpoint exists.** Cortex's `/v1/models/pull` died with the v0.6 move to direct llama.cpp integration (janhq/jan#4941).
  - Data folder (shared by CLI + desktop): macOS `~/Library/Application Support/Jan/data`; GGUF layout `llamacpp/models/<org>/<repo>/model.gguf` + `model.yml` (`model_path`, `name`, `size_bytes`, `model_sha256`); MLX under `mlx/models/<model_id>/`. Since v0.8.0, llama-server runs in "router mode"; per-model settings live in `llamacpp/router.preset.ini` **generated by the desktop app** → configure in desktop, serve headless.
  - `JAN_HEADLESS=1` claims circulate on SEO blogs only — unverified, not in official docs. Ignore.
- Weaknesses vs LM Studio: less polish, manual model-management edges, MLX younger.
- MOT Deck role: **primary runner** (headless, Bridge-managed).

### Hermes (NousResearch hermes-agent)
- MIT-licensed autonomous coding agent; async, self-directed, persistent daemon. Reads codebases, edits files, runs commands, plans multi-step tasks, writes reusable **SKILL.md** skills it remembers.
- Provider config (verified): `hermes model` = interactive wizard (providers, OAuth, keys, custom endpoints); `/model` in-session only switches already-configured ones. **`~/.hermes/config.yaml` is the single source of truth** (`model: { provider: custom, base_url: http://localhost:PORT/v1, ... }`); old `OPENAI_BASE_URL`/`LLM_MODEL` env vars removed. Named/documented providers: LM Studio (`lmstudio`, optional `LM_API_KEY`), Ollama (:11434/v1), vLLM, SGLang, llama.cpp llama-server, LiteLLM; **Jan listed in the compatibility table at :1337/v1**.
- **Tool calling effectively required** of the model: vLLM needs `--enable-auto-tool-choice --tool-call-parser hermes`; llama-server needs `--jinja`; LM Studio ≥0.3.6 — else tool calls arrive as raw text.
- MOT Deck role: managed async daemon; also the **pattern donor** (MIT → lift SKILL.md conventions/code freely, with attribution).

### Odysseus (github.com/pewdiepie-archdaemon/odysseus)
- MIT (corrected 2026-07-19) Python web-service stack; synchronous, user-driven local AI workspace (Codex/Claude-Desktop-like). Signature feature: **DeepResearch via local SearXNG**, using an adapted Tongyi DeepResearch pipeline (Apache-2.0 origin). Bundles SearXNG (AGPL-3.0).
- Run modes (verified): docker compose (`cp .env.example .env && docker compose up -d --build`) **or plain Python 3.11+** (`pip install -r requirements.txt; python setup.py; python -m uvicorn app:app --host 127.0.0.1 --port 7860`; a macOS native script uses 7860). **MOT Deck decision (locked 2026-07-19): native Python only — Debi has ruled out Docker MOT Deck-wide** ([04_Roadmap.md](04_Roadmap.md) §Decisions). Single FastAPI app = UI + API on :7860 (`APP_PORT`/`APP_BIND` override). Sidecars: SearXNG :8080, ntfy :8091, ChromaDB :8100 — all 127.0.0.1 by default; running native means the Bridge supervises the sidecars instead of compose.
- Key env vars: **`SEARXNG_INSTANCE`** (external SearXNG supported — default `http://localhost:8080`); `LLM_HOST` / `LLM_HOSTS` (comma-separated endpoint discovery); optional `OPENAI_API_KEY`; `RESEARCH_LLM_ENDPOINT`; `EMBEDDING_URL`/`EMBEDDING_MODEL`. Most provider config happens in the in-app Settings UI.
- MOT Deck role: managed component; UI embedded as a Mission Control webview tab.

### Layering rule (one sentence)
LM Studio & Jan are model **runners** (engine); Hermes & Odysseus are **agent/app layers** that call an endpoint; your MOT Deck sits above all four.

## 2. MCP learnings (LM Studio context)

- LM Studio adds tools via `mcp.json`: Program tab → Install → Edit mcp.json; uses Cursor's mcp.json notation; local + remote servers; per-tool confirmation dialog. Prereqs: Node (`npx`) + `uv` (`uvx`).
- **You already have starter configs** (inventory §5): `mcp-no-api-keys.json` — filesystem, fetch, duckduckgo, wikipedia, sequential-thinking, memory, time, git, sqlite, playwright, context7, everything; `mcp-api-keys.json` — brave-search, tavily, huggingface, github. Plus a Top-40 MCP servers reference doc.
- Jan is also an MCP host (v0.7.3+, per-tool permission gating v0.7.9+) — the same server set can be configured there; a future Bridge nicety is fanning one MCP server list out to both hosts.

## 3. Skills / SKILL.md landscape

- LM Studio "skills" = a **community plugin** (maikelthedev/skills, forked from khtsly) replicating Claude's SKILL.md system via a prompt preprocessor; skills live in `~/.lmstudio/skills`; **activation is per-chat** (real friction — don't build on top of that plugin's mechanics, just share its directory).
- Hermes uses the same SKILL.md pattern natively and is MIT.
- Consequence: **one skills convention can span the whole motdeck** — a single canonical directory (recommended `~/motdeck/skills`, in git), symlinked into `~/.lmstudio/skills` and Hermes's skills location. Decision + recommendation in [04_Roadmap.md](04_Roadmap.md) §Decisions.

## 4. SearXNG learnings

- **Runs without Docker — verified against official docs (2026-07):** SearXNG is a plain Python app installed from a source clone (it is NOT on PyPI): `git clone https://github.com/searxng/searxng` → venv → `pip install --use-pep517 --no-build-isolation -e .` (after `pip install -U pyyaml msgspec typing-extensions pybind11`) → `SEARXNG_SETTINGS_PATH=<settings.yml> python -m searx.webapp`. ([docs.searxng.org/admin/installation-searxng.html](https://docs.searxng.org/admin/installation-searxng.html))
- Native-run config gotchas: set `server.secret_key`; set `server.port: 8080` (the docs' example uses 8888); set `limiter: false` on a localhost-only instance (avoids the Valkey/Redis dependency the default template assumes); add `json` to `search.formats` or API consumers (Odysseus, MCP) get 403s on `format=json`. The uWSGI/NGINX/system-user machinery in the docs is for public Linux servers — skip it; the built-in webapp server is fine for one local user.
- **MOT Deck decision (locked 2026-07-19): native from-source, no Docker** ([04_Roadmap.md](04_Roadmap.md) §Decisions). Emergency fallback: a public instance via `SEARXNG_INSTANCE`/`SEARXNG_URL` (privacy tradeoff; public instances often disable JSON format).
- Odysseus's DeepResearch AND an MCP web-search server can share **one** local SearXNG instance — confirmed officially supported on the Odysseus side via `SEARXNG_INSTANCE`.
- Plan: one Bridge-managed native instance on :8080 serving both consumers ([02_Architecture.md](02_Architecture.md)).

## 6. Model & hardware notes (64GB Apple Silicon)

- **Context window is a model property** (Qwen3-32B ~128K; Qwen3.6-35B-A3B MoE also large); **RAM governs KV-cache allocation**, i.e., how much of that window you can actually use.
- On 64GB you have ample headroom to raise context sliders **well beyond defaults**. The "context overflow" pain you hit was caused by (a) low default context settings and (b) verbose MCP tool outputs wasting tokens — **not** model capacity.
- Practical settings: run the daily-driver ~30B at 64K+ context; prefer MCP servers with terse outputs for chat use; standardize a small fast model for agent loops ([04_Roadmap.md](04_Roadmap.md) §Decisions).
- **Tool calling is mandatory for the `primary` role (locked 2026-07-19):** Hermes's entire loop and every MCP tool depend on structured tool calls; a model that can't emit them reliably is disqualified as primary regardless of prose quality.
- MLX vs GGUF: MLX is faster on Apple Silicon; Jan's MLX backend is newer than LM Studio's — benchmark per-model before standardizing (spike in [04_Roadmap.md](04_Roadmap.md)).

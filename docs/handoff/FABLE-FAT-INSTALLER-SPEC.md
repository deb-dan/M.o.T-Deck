## PART 0 — REGRESSION FIX FIRST (small, do before the installer): MLX download visibility
**Bug (Fable-owned, from the QA fix-slice):** removing `_download_progress`/`api_switch_status` progress branch killed the only progress signal for MLX model acquisition. MLX repos are multi-file dirs the engine downloads on load — they ride the runner-SWITCH path (switchModel → start_component.sh → mlx_lm/mlx_vlm server auto-downloads from HF), NOT the per-file GGUF download manager (#downloads-sec / /api/dl). So an MLX "Download & Load" now shows nothing, and leaving/returning the browse view loses all trace.
**Observed symptoms (Debi, 2026-07-24 — MLX acquisition is fully broken):** (1) MLX repo detail → "Files & fit: **Failed to load files.**" (hf_files errors or its MLX branch throws for this repo — diagnose: `GET /api/models/hf/files?repo=mlx-community/gemma-4-E4B-it-OBLITERATED-mlx-8Bit`; check the tree parse + the panel mlx render path). (2) Download & Load → "**SWITCH FAILED — downloads arrive with the download manager**" because the switch path rejects "/" HF ids and the download manager has no MLX path → net: NO way to acquire an MLX model today. Fix BOTH as part of this PART 0.
**Decision (Fable): unify acquisition — route MLX downloads through the SAME download manager as GGUF, so there is ONE downloads UI with persistent, resumable, visible progress for every format.** Implementation for Opus:
- Extend `/api/dl/start` to accept MLX repos: when the HF repo is MLX (detect: tree has *.safetensors + config.json, no *.gguf — you already parse tree in dl_start and in hf_files kind detection), enqueue ALL repo files (every *.safetensors split + config.json + tokenizer* + *.json) into `data/models/<repo-leaf-id>/`, same streaming/pause/resume/parallel machinery. model_id = repo basename. On completion, `_registry_add` a `format:"mlx"` entry: path = the model DIR (not a file), mmproj=None, vision = true iff config.json has `vision_config` or `image_token_id` (read it post-download), size_bytes = sum, source "download".
- Panel: for MLX search results, REPLACE the "engine-managed, no button" note with a single **Get** button (repo-level) that calls `dlStart(repo, "")` (empty filename = whole-MLX-repo mode; dl_start branches on that). Detail panel Files&fit for MLX already lists the summed size — keep, add the Get.
- Since acquisition is now the download manager for both formats, the runner-switch path no longer needs to download: when switching to a model already in the registry, it just serves the local dir/file (already true). Keep the switch path's HF-id rejection (ids with "/" still rejected at switch — downloads go through the manager).
- Downloads section persistence: it already polls server-side /api/dl; ensure #downloads-sec renders in BOTH library and browse sub-views (currently likely only one). Verify a download survives leaving/returning the Models pane and an app relaunch (server-side DOWNLOADS dict is process-memory — acceptable; note that a bridge restart drops the in-flight list but .part files remain and a re-Get resumes via Range).

## PART 1 — FAT INSTALLER: goal & shape
**Deliverable:** `./scripts/build_app.sh --fat` → `dist/MOT Deck.dmg` (~2–4GB) that, on a fresh Apple-Silicon Mac with only Xcode CLT present, installs to /Applications, launches, and on first run provisions ALL components OFFLINE from bundled payloads, reaching a green Mission Control with no manual terminal steps. Model weights download later via the (now unified) download manager.

**Core problem = Python venv relocatability.** Three chosen mechanisms (Fable decision — use uv-standalone-python + relocatable venvs as PRIMARY; wheelhouse as the offline source):
1. **Bundle uv's standalone CPython** (download the `uv`-managed python-build-standalone arm64 tarball at build time into the app payload). Standalone CPython is relocatable by design.
2. **Bundle a WHEELHOUSE** — at build time, `pip download` (or `uv pip download`) every component's deps (Hermes[all], Odysseus requirements+ddgs, SearXNG, mlx-lm, mlx-vlm) as arm64 wheels into `Resources/wheelhouse/`. First-run creates venvs from the bundled standalone python and `pip install --no-index --find-links wheelhouse` → fully offline, and venvs built ON the target machine are correctly-pathed (sidesteps relocation entirely for the venvs themselves).
3. **Bundle the pinned llama-server binary** (data/llamacpp from install_llamacpp.sh output) + the vendored Hermes/Odysseus/SearXNG source (the git-pinned checkouts, source only, no .git) into `Resources/seed/`.

So first-run = extract seed to ~/MOT Deck (or /Applications-adjacent app-support dir — Fable decision: **~/Library/Application Support/MOT Deck/** as the runtime root; the app's motdeckRoot resolves there when no dev repo is baked) → build the 4 venvs from bundled standalone-python + wheelhouse (offline) → llama-server already present → seed_registry → panel opens on the §E first-run checklist which shows each component going green. NB: Hermes web_dist must be prebuilt into the seed (npm build at fat-build time) since first-run is offline (no npm assumed).

## PART 2 — build_app.sh --fat (build-time, runs on Debi's Mac or CI)
Steps the script performs:
1. Compile the Swift shell (as today) but with a `FAT_BUILD` flag baked into Config.swift so main.swift resolves motdeckRoot = ~/Library/Application Support/MOT Deck and enables the first-run provisioner branch.
2. Fetch uv standalone python (pin a CPython version, e.g. 3.12.x) arm64 → Resources/python-standalone/.
3. Build the wheelhouse: for each component, `uv pip download -r <reqs> --python-platform macos --only-binary=:all: -d Resources/wheelhouse/` (Hermes[all], Odysseus reqs + ddgs, searxng reqs, mlx-lm, mlx-vlm). Handle sdists-only deps by allowing source for those few (document which). **⚠️ torch/mlx wheels are large + arch-specific — verify they resolve for macos arm64; this is the riskiest build step, tag it.**
4. Prebuild Hermes web_dist (npm --workspace web) and include it in the Hermes seed.
5. Copy pinned vendor source (hermes/odysseus/searxng at their motdeck.yaml pins, source-only, strip .git/node_modules) → Resources/seed/vendor/. Copy scripts/, bridge/, app config, motdeck.yaml → Resources/seed/.
6. Copy the pinned llama-server (data/llamacpp/build/bin + dylibs) → Resources/seed/data/llamacpp/.
7. `hdiutil create` the dmg (UDZO).
8. **Ad-hoc codesign** the .app (`codesign --force --deep --sign - MOT Deck.app`) so it opens without "damaged" on another Mac (Debi hit this). Document that full notarization needs an Apple Developer account (out of scope; ad-hoc + right-click-open is the personal-use path; note the `xattr -dr com.apple.quarantine` fallback for Debi's 2nd Mac).
Flags: `build_app.sh` (thin, unchanged) · `build_app.sh --dmg` (thin dmg, unchanged) · `build_app.sh --fat` (this). Keep them independent.
